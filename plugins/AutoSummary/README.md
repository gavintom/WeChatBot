# AutoSummary · 微信链接 / 卡片自动总结插件

自动总结微信里收到的**网页链接**和**卡片消息**（公众号文章、小程序卡片等），
摘要由宿主的**内置大模型**生成。

宿主版本要求 `>= 1.1.0`（需要 `ctx.llm_chat()` 门面）。

> **默认关闭**：插件自身 `enabled` 默认为 `false`，需显式开启才会工作。
> **斜杠词直接触发**：`require_host_trigger` 默认为 `false`，`/总结`、`/追问`
> 本身就是唤醒词，发出来就直接执行，群里不需要再 @ 机器人或喊宿主唤醒词。

---

## 用法

所有触发词都以 `/` 开头，开头匹配即可。

| 输入 | 结果 |
|---|---|
| `/总结 https://example.com/a` | 抓正文 → 内置大模型总结 |
| `/总结  https://example.com/a` | 同上，触发词后跟任意空格 / 冒号 / 全角空格 / 零宽字符都能准确取链接 |
| `/总结 这篇讲了什么 https://...` | 带自定义问题，只针对该问题作答 |
| `/总结` | 总结本会话上一条链接（30 分钟内） |
| `/追问 这篇的核心观点是什么` | 针对刚总结的原文追问，可连续追问 |
| `/问 这篇的核心观点是什么` | 同上（`/问` 会自动排除「/问题…」这类误命中） |
| 卡片消息 | 解析标题 / 链接 → 总结 |
| 裸链接（无触发词） | 自动总结（`auto_summary` 开启时，默认关闭） |

> **「/总结」不带链接一定能取回刚发的链接**：即使 `auto_summary: false`（裸链接不自动
> 总结），只要消息里有链接或卡片，就会记进本会话的「最近链接」缓存，30 分钟内
> 敲「/总结」即可总结它。
>
> **不唤醒续聊**：插件是旁路 responder，发完摘要**不会**刷新宿主的「对话延续
> 窗口」，也不会在末尾附加免 @ 提示。后续消息仍需 @ 机器人或命中唤醒词才会
> 实质触发 AI。插件自己的「/追问 / /问」是独立触发词，不受续聊窗口影响。

摘要固定四段：**标题 / 📖 总结 / 💡 关键要点 / 🏷 标签**，
纯文本输出（不带 markdown 符号，微信里看是干净的）。整体刻意精简：
总结不超过 60 字、关键要点只列 2 条、标签 2 个；追问回答不超过 80 字。

> **追问触发词只在「本会话刚总结过东西」时才生效。**
> 否则一句「/问一下这个政策」会被插件劫持去回答上一篇文章，而不是正常问 AI ——
> 没有可追问的原文时，插件会让这条消息继续走 AI 主链路。
>

## 安装

1. 插件已经在 `plugins/AutoSummary/`，无需拷贝。
2. 打开 `data/config.yaml`，把 `plugins.enabled` 改成 `true`（插件系统总开关）。
3. 把 `plugins/AutoSummary/config.example.yaml` 拷成 `data/plugins/AutoSummary.yaml`，
   把 `enabled` 改成 `true`（插件自身默认关闭，这一步必须做）。
4. 重启主服务，或调 `POST /internal/plugins/reload` 在线加载。

```bash
# 启用插件（会自动重载）
curl -X POST -H "X-Internal-Token: <token>" -H "Content-Type: application/json" \
     -d '{"name":"AutoSummary","enabled":true}' \
     http://127.0.0.1:29999/internal/plugins/state
```

## 配置

全部配置在 `data/plugins/AutoSummary.yaml`，改完最多 30 秒生效，**不用重启**。
完整字段见 `config.example.yaml`，常用的几个：

> **`enabled` 是权威开关**：设为 `false` 时插件直接不加载、后台显示「配置禁用」。
> 后台「插件管理」里点启用 / 禁用，会同步改写本文件顶部的 `enabled` 行，两边始终一致。
> 手动改本文件的 `enabled` 后，点一次后台的「重新扫描并重载」即可生效。

| 配置 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 插件自身总开关，**默认关闭**，需显式开启 |
| `auto_summary` | `false` | 消息里有链接就自动总结（不需要敲触发词），默认关闭 |
| `require_host_trigger` | `false` | **默认关闭** — 斜杠词本身就是唤醒词，直接触发、无需 @；设 `true` 才要求 @ 或宿主唤醒词 |
| `summary_triggers` | /总结 /摘要 /帮我总结 /summarize /summary | 总结触发词（全部带 `/`） |
| `qa_triggers` | /追问 /问 | 追问触发词（全部带 `/`） |
| `expiration_time` | `1800` | 缓存过期秒数（影响「/总结」不带链接、追问） |
| `max_text_length` | `6000` | 送给模型的正文最大长度 |
| `jina_enabled` | `false` | Jina 兜底开关（本地抓取为主，无 key 时别开） |
| `jina_api_key` | 空 | 有 Jina key 填上，Jina 兜底成功率才高 |
| `llm_model` | 空 | 留空 = 用后台「AI 大模型」页选定的默认模型 |
| `white_url_list` / `black_url_list` | 黑名单含视频号两个域名 | URL 前缀黑白名单 |
| `white_user_list` / `black_user_list` | 空 | 按人控制（wxid） |
| `white_group_list` / `black_group_list` | 空 | 按群控制（xxx@chatroom） |

## 工作方式

### 抓正文

1. **本地抓取（主路径）**：直接请求原网页，标准库 `html.parser` 抽正文 ——
   丢掉 `script/style/nav/header/footer` 等噪声块，其余按块级标签断行。
   微信文章额外识别 `#js_content` 正文容器（避开导航 / 推荐 / 二维码噪声），
   标题取 `#activity-name` / `og:title`。无需任何外部 key。
2. **Jina Reader（可选兜底，默认关闭）**：本地抓不到时才试。Jina 免费额度已
   基本取消，无 key 时 401 是常态，所以默认不启用；填了 `jina_api_key` 再开
   `jina_enabled: true` 才有意义。任何一路的异常都会被吞掉并继续下一路，
   不会再出现「Jina 401 导致本地兜底根本没跑」的情况。

正文抓不到时：显式触发会回一句提示；**自动模式下保持安静**（群里每条链接
都回一句「抓取失败」太吵）。

### 调模型

走 `ctx.llm_chat()` → `brain.chat_only()`：不检索知识库、messages 原样发给模型，
复用宿主已经配好的流式 / 非流式 / 重试 / 超时逻辑，
用量同样记进后台「AI 用量」页（`source=plugin`）。

### 权限与范围

插件动手前会核对两件事：

1. **插件自己的黑白名单**（按人、按群）；
2. **宿主的部署范围** —— 群必须在后台「群聊配置」表内，私聊必须有启用策略。
   在没部署的群里总结等于替机器人越权发言，所以直接放行不做。

把群写进 `white_group_list` 就是**显式授权**本插件在那里工作（覆盖第 2 条）。

### 两条执行路径

- **默认**（`require_host_trigger: false`）：斜杠词（`/总结`、`/追问`）在
  `on_message` 阶段识别并直接执行 —— 词本身就是唤醒，群里不需要 @ 或宿主唤醒词。
  裸链接 / 卡片是否自动总结另由 `auto_summary` 控制（默认关闭）。
- 严格模式（`require_host_trigger: true`）：识别后推迟到 `on_post_resolve` 执行，
  必须宿主策略放行（群里 @ 机器人或命中「小禾」这类唤醒词）才动手。
  注意宿主唤醒词不含 `/总结`，此模式下裸发 `/总结` 不会触发，需搭配 @ 或唤醒词。

## 注意事项

- 插件跑在宿主进程里，**不会自动 pip 装依赖**，所以正文解析用标准库实现。
- 抓网页是同步阻塞的（默认连接 5s / 读取 20s）。超时时间可在配置里调小。
- 会话缓存（最近链接、最近一次原文）存在**进程内存**里，重载插件即清空。
- 自动总结会在群里 @ 发送者（跟随宿主 `reply.at_sender` 配置）。

- 验收日期：2026-11-19
- 范围：仓库全部源码共 40 个 Python 文件（19,292 行）+ 前端 6,626 行（app.js 3,951 / app.css 1,813 / 模板 862）
- 方法：
  1. `pyflakes` 全量静态检查（未定义名、未使用导入、未用变量）
  2. 自建 AST 交叉引用工具：提取全部函数/类/常量定义，统计「非定义行、非 import 行」的真实调用点
  3. 前端符号级核对：206 个顶层函数的调用点、Flask 路由 ↔ 前端 `fetch` 双向差集、CSS 类 ↔ HTML/JS 引用
  4. 配置项反向核对：`config.yaml.example` 的 121 个叶子键 ↔ 代码实际读取
  5. 重复代码块检测（10 行窗口）+ 复杂度度量（函数长度、异常密度）
  6. 运行时验证：模块导入、路由注册、项目自带 4 套验收脚本

## 一、总体结论

代码整体质量**高于同类项目平均水平**：模块边界清楚（store / policy / brain / media_store / pluginhost 各司其职），中文注释解释了「为什么这么写」而非「这行做什么」，插件宿主有版本与能力约束，敏感文件（`data/config.yaml`、`.admin_secret`、`*.db`）均已正确忽略。

## 二、已修复

### A. 真实缺陷（会影响运行）

| # | 位置 | 问题 | 影响 | 处置 |
|---|---|---|---|---|
| A1 | `webhook_server.py` `_save_conversations()` | 多线程共用同一个 `.conversations.json.tmp`，且写文件在锁外 | 并发回复时两个线程同时写同一临时文件 → 内容交错或 `os.replace` 找不到文件；记忆文件损坏后下次启动**整份对话记忆丢失** | 快照在 `_conv_lock` 内取、落盘由新增 `_save_lock` 串行、每次用 `tempfile.mkstemp` 唯一临时名，失败自动清理 |
| A2 | `media_store._schedule_upgrade()` | 每张低画质图片起一个守护线程，循环 `sleep(15+45+90+180+300+480)` | 单线程存活约 **18.5 分钟**；群里连续发图会产生几十上百个线程（每个仍在做网络探测） | 改为**单调度线程 + 最小堆按到期时间排队**，线程数恒为 1；顺带修正「检查点相对保存时刻」的语义（原实现是累加等待，与注释矛盾） |
| A3 | `admin/app.py` 登录限流 | `_fails` 字典无锁，且 IP 记录只增不减 | 多线程下并发写可能丢计数；伪造 `X-Forwarded-For` 的请求可让字典无限膨胀 | 加 `_fails_lock` 串行化；窗口内无失败的 IP 自动移除；超 5000 条兜底清理，并在注释标明「XFF 可伪造，限流只用于降速」 |

## 四、发现但未修改（建议 / 需你决策）

> 以下 7 项已在第二轮全部落地，实施与验证记录见第五节。

按优先级排序：

1. **`admin/app.py` 2,082 行单文件**（最高优先级可维护性问题）
   已完成部分拆分（contacts / kb / moments / pricing / proc），但**89 条路由和大部分视图函数仍堆在 app.py**，导出、分页、配置、LLM、聊天记录混在一起。建议按域拆成 Flask Blueprint（`bp_contacts` / `bp_kb` / `bp_llm` / `bp_sys`），app.py 只保留应用装配与安全中间件。改动面大，建议单独一次提交并配合全量回归。

2. **`webhook_server._handle_message()` 224 行**
   媒体入库 → 引用图 → 插件钩子 H1 → ASR → 策略 → 插件 H3 → 类型分支 → 组装提问 → 生成 → 发送，八段职责串在一个函数里。建议按注释里的自然分段抽成 `_stage_media()` / `_stage_asr()` / `_stage_answer()`，主函数只留编排。纯重构，不改行为。

3. **4 份重复的 SQLite 连接初始化**
   `store.py` / `chatlog.py` / `media_store.py` / `phone_mon.py` 各自实现 `_connect()` + WAL + busy_timeout（10 行块完全相同的已有 2 处）。建议提取 `db_util.connect(path)`，以后调 PRAGMA 只改一处。四者 DB 路径不同但参数一致，抽象成本低。

4. **对话记忆每次回复都全量落盘**
   `_remember()` → `_save_conversations()` 写整份 JSON（当前 7 个会话无感，几百个会话时是 O(n) 写放大）。可加「最多 1 秒合并写一次」的节流；代价是进程被强杀时可能丢最后 1 秒记忆。需要你权衡可靠性与 IO。

5. **`policy.py` 的 `quote_self_trigger`**
   代码支持按规则关闭「引用本机消息免唤醒」，但后台规则界面没有这个开关，写入的规则永远取默认 `True`。要么在「群聊规则」编辑里暴露该字段，要么删掉这个 `get` 直接写常量。

6. **`/api/plugin/license` 无前端调用**
   后台展示授权状态用的是 `/api/plugins` 内嵌的 `license` 字段。该接口是「主动刷新」的运维排障入口，**建议保留**，已在 docstring 标注用途；若确认不用可删。

7. **`tools/verify_llm_chat.py` 有 6 处 `import json` 遮蔽**
   pyflakes 报 `redefinition of unused 'json'`。属于测试脚本历史遗留，不影响生产，顺手清理即可。

## 五、第二轮：第四节取舍项落地（4.1–4.7）

按「一次提交只做一组、每阶段打包测试版验证」的节奏执行，三次提交：

### 4.1 admin/app.py 拆 Blueprint（cf2416f）
`app.py` 2,101 → 209 行，只保留应用装配、登录限流、CSRF / 错误处理与页面路由。
业务接口拆成 8 个蓝图（sys / plugins / contacts / media / kb / records / moments / config），
共用层抽成 `admin/web.py`：响应助手、登录校验、主服务转发、分页、应用常量与日志。

- 依赖方向单向 `app → bp_* → web`，蓝图不反向 import app，可单独导入测试
- 助手统一为公开名：`ok / fail / body / csv_response / paged / page_args / days_arg / main_cfg / call_main`
- **等价性核对**：89 条路由与拆分前逐条比对一致；123 个顶层函数「语句条数」逐个核对，
  仅 6 处差异且都能解释（新增 docstring、`urlparse` 上提到模块级、`cfg` 导入上提）
- 新增 `tools/verify_admin_routes.py`：路由清单基线 + 登录态 GET 全量冒烟（50 条）

### 4.2 _handle_message 拆阶段（f0e4efe）
224 行拆成编排层 + 8 个阶段函数：`_stage_filter / _stage_media / _stage_asr /
_stage_kind_branch / _stage_question / _answer_options / _generate / _send_answer`。
编排层只表达「阶段顺序 + 早退」。核对方式：重构前后日志文案集合完全一致、关键调用次数一致（44 次）。

### 4.3 SQLite 连接收敛（f0e4efe）
新增 `db_util.connect()`，store / chatlog / media_store / phone_mon 四处 `_connect` 合并为一行调用。
`timeout` 同时决定 `busy_timeout`，不再两处各写一个数。phone_mon 原用默认 `synchronous=FULL`，
现与其他库统一为 `NORMAL`（WAL 下的常规取舍，监控表可接受）。

### 4.4 对话记忆落盘合并（f0e4efe）
`_remember()` 只标记待写，`conv-saver` 线程在 1 秒窗口后合并写一次；`atexit` 注册
`flush_conversations()` 兜底。实测 100 次连续写入只落盘 1 次。强杀进程最多丢 1 秒记忆；
需要旧行为可设 `WXBOT_CONV_DEBOUNCE=0`。

### 4.5 群聊规则暴露「引用本机消息也触发」
`group_rules` 新增 `quote_self_trigger`（默认 1，幂等迁移补列），保存 / 读取 / 列表全链路打通。
实测：关掉后引用机器人消息不再触发（`handled=False`），打开后按 `quote:self` 触发。

### 4.6 `/api/plugin/license` 接上前端
运行监控的插件卡片新增「刷新授权」按钮，客户在微信里续期后可即时回读，不必刷新整页。
该接口从「无人调用的运维入口」变成正常功能入口。

### 4.7 测试脚本清理
`tools/verify_llm_chat.py` 删除未被使用、又被形参遮蔽的 `import json` 与 `import types`；
`tools/verify_autosum.py` 清理 3 处未用导入；`store.py` 5 处函数内重复 `import json` 上提为模块级。
